# DSH Session Git Sync

通过 Git 仓库在不同电脑之间迁移 **DeepSeek Harness (DSH)** 的会话历史。

插件在两个位置提供界面：

- **左侧栏 →「会话同步」**（与「插件」「自动化任务」并列）：上传与下载的主界面。
  - 按单个会话，或按整个工作区选择要上传的会话。
  - 把会话记录写入一个 Git 仓库分支。
  - 在另一台电脑读取同一个分支，选择远端会话并导入为本地会话。
  - 导入时可以按原始路径自动匹配工作区，也可以指定一个本地工作区作为目标。
- **设置 →「会话同步」**：只保留仓库配置（地址、分支、提交身份、测试连接）。

## 安装

这是一个本地 DSH bundle，不在 npm 上。任选一种方式：

### 从 Release 安装

1. 从 [Releases](https://github.com/AmosIscr/dsh-session-git-sync/releases) 下载 `dsh-session-git-sync-1.0.1.zip`。
2. 解压出 `dsh-session-git-sync` 目录。
3. 在 DSH 的 Plugin Manager 中安装这个本地目录；也可以让 Agent 用 `install_bundle` 指向解压后的绝对路径。
4. 刷新页面。

### 从源码安装

```powershell
git clone https://github.com/AmosIscr/dsh-session-git-sync.git
```

然后在 DSH 中安装克隆下来的目录，刷新页面。

安装后，插件数据位于：

```text
$DSH_HOME/session-git-sync/
  config.json      # 本机仓库地址、分支、提交身份、最近同步时间
  repo/            # 插件私有的 Git 工作区
```

`$DSH_HOME` 通常是 `C:\Users\<用户>\.dsh`。

> 插件代码本身不通过会话仓库同步；会话仓库只保存会话历史。

## 使用

1. 打开 **设置**，选择 **会话同步**。
2. 填写 Git 仓库地址，例如 `https://github.com/you/dsh-sessions.git`，以及分支（默认 `main`）。
3. 点击 **测试连接**。分支不存在也没关系，首次上传会自动创建。
4. 打开左侧栏的 **会话同步** 入口（也可以点设置里的 **打开同步面板**）。
5. 在 **上传** 页选择会话或工作区，然后点击 **上传到 Git**。
6. 在另一台电脑安装同一插件，填写同一个仓库地址，打开 **会话同步 → 下载**，点击 **读取远端**。
7. 勾选需要的会话或工作区；选择 **导入到** 的目标工作区（或保留自动匹配），点击 **导入所选**。
8. 如果侧边栏没有立即显示导入的会话，刷新页面即可。

## 仓库格式

```text
dsh-sessions/
  manifest.json                 # 会话/工作区索引
  sessions/<safe-id>.json       # 单个会话的完整事件日志
```

会话文件保存的是持久化服务返回的当前格式事件数组，而不是直接复制 `.jsonl.zstd` 文件。因此导入时仍由本机持久化后端负责编码、校验和写入，能够适配不同机器的存储实现。

## 合并规则

- 上传只合并所选会话，不会删除远端其他会话。
- 同一会话如果远端事件数更多，上传会跳过该会话并在结果中提示，避免覆盖远端更新。
- 导入前会核对会话格式版本：远端会话由**其他 DSH 版本**写入时会被直接拒绝并说明双方版本，本机不会写入读不出来的会话日志。
- 导入时如果本地不存在该会话，会创建本地会话。
- 如果本地日志是远端日志的严格前缀，会追加远端新增的事件。
- 如果双方事件出现分叉，会报告冲突并保留本地版本，不自动覆盖。
- 正在打开的会话不会被导入覆盖。
- 导入时会自动加入对应路径的工作区；目标路径不存在时也可以手动选择本地工作区。

## 隐私与限制

- 会话记录是明文 JSON，包含对话内容、工具调用参数和结果。**请使用私有会话仓库**，不要把访问令牌写进仓库 URL。
- 不会上传工作区源码文件。
- 不会上传附件（图片、文件）；会话中的附件引用在另一台电脑上可能无法读取。
- 使用系统 Git 和现有的 Git 凭据（HTTPS credential helper / SSH key）。插件不保存 Git 密码或令牌。
- Git 操作在插件私有的 `repo/` 工作区执行；每次读取远端都会重置该工作区，因此不要手工在里面保存修改。
- 不建议在仓库中存放 `.env`、密钥或凭据。

## 环境要求

- 已安装 Git，并确保 `git` 在启动 DSH 的环境 `PATH` 中。
- 当前实现使用 DSH `0.2.1-rc.5` 的 Session、Workspace、Settings slot API。
- 两台电脑应当运行写入**同一 Session 格式版本**的 DSH（当前为 `v4`，面板「仓库」一栏会显示本机版本）。DSH 升级可能提升该版本；版本不同时导入会被拒绝，而不是写坏日志。
- 浏览器端需要 DSH Web UI；插件注册了 `sidebar.panellist`（左侧栏入口）、`main`（上传/下载页面）和 `settings.section`（仓库配置）。

## 故障排查

- **Git not found**：确认 `git --version` 在启动 DSH 的环境中可以执行。
- **无法访问远程仓库**：先在本机终端执行 `git ls-remote <仓库地址>`，确认凭据可用。
- **远端分支还没有数据**：先在另一台电脑完成一次上传。
- **导入后找不到会话**：刷新页面；如果原路径在本机不存在，导入时请选择一个本地目标工作区。
- **提示“会话使用 DSH 会话格式 vN，本机写入格式为 vM”**：两台电脑的 DSH 版本不同（DSH 每个版本只写一种会话格式）。把 DSH 升级到同一版本后重新导入；插件不会为了迁就旧版本而写入无法读取的日志。
- **冲突**：说明同一会话在两台电脑上都产生了不同事件；当前策略保留本地版本，需要人工决定保留哪一份。
